# PR report

## 1. Gather

Read the handoffs listed in `input.md`: the task, `plan.md`, `design.md`, `dev-notes.md`,
`security-report.md`, `test-report.md` and `evidence/manifest.json`.

## 2. Write `pr.md` in your output directory

A brief the reviewer reads in a minute: these six sections, **at most 40 lines** (the backend checks both).
Lead each section with the point. Long tables and logs stay in the local handoffs; name them, do not paste them.

```markdown
## Why
<one or two lines: the problem this task solves, from the task file>

## What changed
<what the user can do now, two to four lines>
Covers: FR-001 (AC-1, AC-2), FR-002 (AC-3)

## Scope
<the areas and main files touched; what is deliberately out of scope>

## Tradeoffs
<the choice made and the alternative rejected, from design.md; or "None">

## Blast radius
<what else could break, and the one fact it is safe because of, with how that was shown (a test you can name)>

## Verification
- Tests: <n> e2e cases passed (TC-01, TC-02, ...); `make check` green; <n> tests written first (tdd)
- Security: introduced <n critical, n high, n medium, n low>; pre-existing <n> (listed in `security-report.md` as follow-ups)
- Evidence: `.factory/runs/<TASK>/e2e/<n>/evidence/` (stored locally, not uploaded)

---
Generated by the Forge pipeline (run <run-id>).
```

## 3. Push and open

```bash
git push -u origin <task-branch>
gh pr create --base <base-branch> --head <task-branch> --title "<type>: <task title> (<TASK>)" --body-file <out>/pr.md
gh pr view --json number,url
```

- Never merge, never force-push. If the branch already has an open PR, use it and report its URL.
- If `git push` or `gh` fail (no remote, no auth), report `blocked` with the exact error.
- Put `pr_url` and `pr_number` in the frontmatter.
