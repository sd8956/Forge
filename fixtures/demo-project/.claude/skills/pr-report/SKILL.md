# PR report

## 1. Gather

Read the handoffs listed in `input.md`: the task, `plan.md`, `design.md`, `dev-notes.md`,
`security-report.md`, `test-report.md` and `evidence/manifest.json`.

## 2. Write `pr.md` in your output directory

```markdown
## Summary
<two to four lines: what the user can do now>

## Covered requirements
- FR-001 <title>: AC-1, AC-2
- FR-002 <title>: AC-3, AC-4

## Test cases
| Case | Covers | Type | Result | Evidence |
| --- | --- | --- | --- | --- |
| TC-01 | FR-001 AC-1 | e2e | passed | 3 screenshots, video, trace |

All evidence is stored locally in `.factory/runs/<TASK>/e2e/<n>/evidence/` (not uploaded).

## Security
Tools: semgrep, gitleaks, osv-scanner. Confirmed findings: <n critical, n high, n medium, n low>.
<one line per medium or low finding, or "None">

## Risks and follow-ups
<from dev-notes.md, security and open questions; or "None">

---
Generated by the Forge pipeline (run <run-id>).
```

## 3. Push and open

```bash
git push -u origin <task-branch>
gh pr create --base <base-branch> --head <task-branch> --title "<type>: <task title> (<TASK>)" --body-file <out>/pr.md
gh pr view --json number,url
```

- Never merge, never force-push. If the branch already has an open PR, use it and report its URL.
- If `git push` or `gh` fail (no remote, no auth), report `blocked` with the exact error.
- Put `pr_url` and `pr_number` in the frontmatter.
