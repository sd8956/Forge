# Spike F0 — Drive Claude Code in tmux without reading the screen

- Date: 2026-11-11/12
- Branch: `feat/f0-spike`
- Result: **gate passed**. Every exit criterion was shown with the real `claude` CLI and with the fake binary in CI.
- Environment: Claude Code **2.1.322**, tmux 3.7c, Node 26.8.1 locally (CI runs Node 22), pnpm 11.26, Linux.

## How to reproduce the manual run

```bash
pnpm install
cp -r fixtures/demo-project .sandbox/demo-project
git -C .sandbox/demo-project init -b main && git -C .sandbox/demo-project add . && git -C .sandbox/demo-project commit -m init
# Trust the project once: run `claude` in .sandbox/demo-project and accept the dialog. Worktrees inherit it.
pnpm forge serve                      # terminal 1
pnpm forge run-step --project .sandbox/demo-project --task TASK-001 --step plan   # terminal 2
tmux -L forge attach -t forge-TASK-001-plan   # optional: watch or answer prompts
```

The planner also needs `engram` on the `PATH`.

## Exit gate

- [x] **With the real `claude` and `--agent forge-planner`, a step ends and the backend marks it `done` only through `report_step`, without reading the screen.** Runs 1, 3, 4 and 6. The backend never captures pane output; `tmux capture-pane` was used only by me, acting as the person answering prompts.
- [x] **If the agent tries to stop without reporting, the Stop hook makes it report.** Run 5. The event log shows `hook Stop`, then `stop_blocked 1`, then `report_blocked`. The transcript shows the block reason delivered as "Stop hook feedback". CI covers the block limit and `stop_hook_active` (`never-report` scenario).
- [x] **A pending permission moves the step to `needs_human` through Notification.** Runs 2 and 4, through `permission_prompt`. In run 4 the person answered and the step still finished `done`.
- [x] **The tmux session closes on its own and the `transcript_path` is recorded.** Every run: the backend kills the session 1.5 s after `report_step`, then the `SessionEnd` hook arrives with `reason: "other"`, and the step keeps the `transcript_path` from the hooks.
- [x] **Killing and restarting the backend during a step neither loses nor duplicates it.** Run 6 with the real CLI, and `test/restart.test.ts` with `SIGKILL` in CI. A step whose session died while the backend was down is marked `orphaned_session_missing`.
- [x] **`pnpm test`, `pnpm lint` and `pnpm typecheck` are green.** 52 tests: unit tests (state machine, Stop policy, store, fixture contract) and integration tests (real tmux plus the fake `claude`, including a real `SIGKILL` restart).

## What worked

- Hooks and MCP are enough to drive the CLI. Nothing needed the screen: completion, blocks, attention and close all arrived as HTTP calls.
- HTTP hooks with a token header, Streamable HTTP MCP in stateless mode with one URL per step, and `tmux kill-session` triggering `SessionEnd` all behaved as documented.
- The transition table plus a guarded `UPDATE ... WHERE status = <read status>` keeps the state consistent; the partial unique index prevents duplicate live steps across restarts.
- The fake `claude` drives the same flags, settings and MCP config as the real one, so the CI suite covers the full lifecycle in about 4 s.

## Claude Code findings and limitations (2.1.322)

1. **The agent's `permissionMode` is ignored when it runs as the main thread with `--agent`.** The session took the CLI default (`auto`), which approves actions with a classifier and never shows prompts. Fix: the runner reads `permissionMode` from the agent file and passes `--permission-mode`. It refuses `bypassPermissions` and `auto`.
2. **In `acceptEdits`, every MCP tool asks for permission**, including `report_step` and Engram. The step settings must allow `mcp__factory` and each memory server explicitly.
3. **Frontmatter `mcpServers` are trust-gated and do not expand `${VAR}`**, and no variable gives an MCP server the session id. `factory` is therefore passed per step with `--mcp-config` (ADR 0001). The project must be trusted once; worktrees inherit the trust.
4. **The agent does not follow instructions found inside task data** that contradict `input.md` and the step protocol. That is good for prompt injection, but it means a drill cannot be scripted through a backlog file. The Stop drill needed a real interruption.
5. **Typing into the TUI while the agent works does nothing useful**: the text was lost. `Esc` followed by a message works. Phase 1's "answer from the embedded terminal" works the same way.
6. **`--mcp-config` is variadic**: a prompt placed after it is read as a file path. The prompt goes first.
7. **The Stop hook rarely fires on a normal run**, because the backend closes the session 1.5 s after `report_step`, before the turn ends. That is fine, but the agent's last message can be cut off.
8. **`idle_prompt` was not observed** in these runs. It is wired and tested with the fake binary.
9. **The Engram search ran with `all_projects: true`**, so a step can read memories from the user's unrelated projects. This must be closed before Phase 1 (see below).

## Other problems found and fixed

- The `tsx` CLI starts the program in a child process, so a `SIGKILL` on it left the real backend alive. `pnpm forge` now runs `node --import tsx`.
- `tmux kill-server` leaves the socket file behind; the tests remove it.

## What I would change in the design before Phase 1

1. **Engram scoping.** Steps must search and save only in the project's own Engram project: state it in `forge-step-protocol`, and prefer a `MemoryAdapter`-side MCP proxy that pins the project and drops `all_projects`. Also deny the Engram admin tools.
2. **Read step templates from the main checkout, or sync the worktree before each step.** A task worktree freezes `.claude/` and `.factory/steps/` when it is created, so fixes on `main` do not reach running tasks. Run 4 hit this.
3. **A trust preflight.** Before launching, check that the project is trusted, and fail with a clear message instead of a session stuck on the trust dialog until timeout.
4. **A cancel API and a "nudge" action** (`Esc` plus a message through `send-keys`) for the panel, instead of attaching by hand.
5. **Lost hooks while the backend is down.** A session that finished its turn during the outage stays `running` until its timeout. Add a nudge on resume, or a shorter post-restart deadline.
6. **Step allowlists per step in YAML**, generated into the settings template, since every MCP tool needs an explicit allow.
7. **Map step `blocked` to a run state.** The brand and interface design has no "Blocked" badge (ADR 0003).
8. **Engram concurrency** (several sessions writing at once) is still open. F0 ran one session at a time.
