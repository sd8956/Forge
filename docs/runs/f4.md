## Findings and fixes

1. **An agent's frontmatter broke YAML** (`description` with ": "): the design stage failed to launch in the
   integration test. Descriptions are quoted and a fixture test parses every agent.
2. **The validators met the hand-written sandbox**: a task may cover only an NFR, and an NFR may be measurable by a rule
   that holds everywhere ("every control has a visible label").
3. **A new repository has no base branch on GitHub**, so the PR had no base: Forge pushes it first (`c2d26b8`).
4. **Feedback from the person during the run** (`5718559`, `000eca8`, `03a1d39`):
   - after "Request changes" the open prototype did not reload: every file now carries its modification time and the
     panel reloads documents and screens when they change;
   - the prototype was squeezed into a ~370 px frame and its fixed widths overlapped: screens sit above a full-width
     frame, "Open full size" opens it alone, and the design stage is asked for layouts from 360 to 1440 px;
   - tabs now follow the stage order (Prototype before backlog);
   - the person had to tell Forge the definition PR merged: a watcher polls it now;
   - long module lists squeezed plan task titles: modules wrap as chips.
5. **The panel went blank after a rebuild**: `@fastify/static` with `wildcard: false` registered routes for the files
   present at start-up, so new hashed assets returned 404. Panel files are looked up per request (`468a2e4`).
6. **Prompts on almost every step** of the new stack (`node -v`, `mktemp -d`, `pnpm prettier`, `git clone`): the template
   allow lists fit `demo-project` only. The person chose auto mode by default with a project opt-out (ADR 0010,
   `0e50e58`); the last step of the run (pr) ran in auto with no prompt.
