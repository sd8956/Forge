# F5 — Memory, Settings, API key and Maestro

Closed on 2026-11-17 with tests for the API key and Maestro, by the person's decision (no real API key run and no
global Maestro install). Feature document: `odd/tasks/f5-memory-settings-auth.md`. Decisions: ADR 0011 and ADR 0012.

## What was built

| Part | What it does | How it was checked |
| --- | --- | --- |
| Memory | Lists, searches and filters what the project's steps saved in Engram (by task or by step), read-only, each linked to its task's run | Integration test; Playwright with a fake Engram; against the real Engram: 19 memories for `demo-project` and 9 for `daily-tasks`, each linked to its run |
| Settings | Forge-wide session cap, usage threshold and authentication, over the environment defaults; project settings read-only from `project.yaml` | Integration tests (the scheduler and the queue view use the stored values); Playwright; the real panel shows the effective limits |
| API key | Subscription by default or an Anthropic API key, stored only in a 0600 file in Forge's home and given to every step, stage and orchestrator session through Claude Code's `apiKeyHelper` | Integration test: the key is in no response and not in the database file's bytes; the rendered settings carry `cat <file>` and never the key; the key in use cannot be removed. Verified in Claude Code's docs that `apiKeyHelper` works from `--settings` and ranks above the subscription login |
| Maestro | A mobile project's test strategy must plan Maestro; the e2e step gets the `maestro-evidence` skill (flows in `.maestro/`, a screenshot per action, the same evidence manifest) | Unit test of the validator; fixture contract test of the tester agent and the skill |

## Not proven in a real run

- A step authenticated with a real API key (needs the person's key and spends API credits).
- A Maestro flow on an emulator (needs the Maestro CLI, Java 17 and the Android SDK, installed globally).

## Fixes found on the way

- The project settings section was hard to read (values right-aligned, defaults looked like values, "Commands" ran into
  its value): it is a two-column list with a commands table now.
- Controlled radio buttons whose state comes from the backend need a click and a wait in Playwright, not `check()`.

## Checks

382 unit and integration tests, 13 Playwright tests, lint and typecheck green.
