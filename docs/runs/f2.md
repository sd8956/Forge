## Bugs found and fixed

- A refused WebSocket upgrade left its socket open, so the backend could not shut down. Refused upgrades now close
  their socket and shutdown destroys upgrade sockets.
- `onPrMerged` marked the run `done` before archiving and removing the worktree. `done` now always means cleaned up.
- The fake `gh` rewrote its whole state on every call, so a test's edit could be lost (harness race).
- The fake `claude` crashed with EIO when tmux closed its pty (its new stdin listener had no error handler), so the
  SessionEnd hook was sometimes never sent. A flaky test that looked like load was this.
- From the panel screenshots: a fresh backend had no way to add a project, the run page showed the task id instead of
  its title, and the "Awaiting review" column was scrolled out of view. All fixed.

## What to improve before Phase 3

1. **A launch preflight for agent files.** Old worktrees lack agents added later. Check the agent file exists in the
   worktree and offer to merge the base branch, instead of failing the launch.
2. **The guard should cover unquoted globs** (`find ... *.js`) with a hint to use Glob; it was the only prompt left
   in TASK-003.
3. **Verify a tight allow rule for posting replies** (`gh api -X POST repos/<slug>/pulls/<n>/comments/<id>/replies`).
   The prefix rule did not match.
4. **Concurrency is not limited yet.** Two runs (TASK-003 and the PR #1 review) overlapped without trouble, but the
   Phase 3 scheduler must cap sessions (3 by default) and pause on rate limits.
5. **Phase 3 needs the orchestrator.** The PDF's orchestrator chat and "Pause queue" are intentionally absent.

## Follow-up: pre-Phase-3 fixes (2026-11-17)

Done in `feat/pre-f3-fixes`:

1. **Agent preflight.** Before launching a step, the backend checks that the agent file exists in the task worktree.
   If it does not, the run moves to `needs_human` (`agent_missing:<agent>`) with the fix, instead of a failed launch.
   `forge resume <run> --merge-base`, or the panel's "Merge main and resume" button, merges the base branch into the
   task branch first. It refuses a dirty worktree and aborts on conflicts.
2. **Unquoted globs.** The tool guard now denies unquoted glob arguments to `find`, `git`, `sed` and `sort`, with a
   hint to quote them or use Glob/Grep. These are the commands Claude Code always asks about (permissions docs). The 79
   real F1 commands classify as before.
3. **Reply allow rules.** A `:*` suffix means "a space, then anything", so `Bash(gh api -X POST repos/:*)` never
   matched. The review-fixer step now allows exactly `gh api -X POST repos/*/pulls/*/comments/*/replies -F body=@*` and
   `gh api -X POST repos/*/issues/*/comments -F body=@*`. A real Claude Code 2.1.322 probe confirmed both run without a
   prompt, while other POSTs (creating a PR or a ref) are still denied.
